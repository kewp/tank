Tank 2007
Revival

A fixed-function OpenGL tank game written for a Core 2 Duo MacBook, nineteen years ago. It now builds on Apple Silicon and runs in a browser on WebGL. Here is what it is, what had to change, and how the graphics port works.

✓ NATIVE macOS 26 / arm64 ✓ BROWSER WebAssembly + WebGL 5,481 lines C++ ~900 lines of GL shim 0 game lines changed for WebGL

What it is

A third-person arena shooter. You drive a tank across a 66×127 tile map, trip ambush triggers that spawn wall turrets, collect weapon and health pickups, and eventually wake a boss — a two-part armoured train that rolls in on rails, opens its doors, and fires at you.

No engine, no scene graph, no asset pipeline, no dependency beyond GLUT. Every polygon is a hand-authored vertex table typed into a const GLfloat array. The entire build is one command, because tankmain.cp #includes the other twelve .cp files directly — the whole game is a single translation unit.

The level is ASCII art

The map lives in GLConstants.cp as a literal const int OriginalMap[66 * 127]. Single-letter const int aliases make it readable as a picture while compiling to a plain array of integers. This is the whole level format — there is nothing else.

B wall T tower X floor I H rail A arch R D M pickup 2–9 ambush trigger 

  
Rows 0–7 and 40–52 of the map, commas removed. The 8 running down the left arena is a one-shot trigger: drive over it and five turrets spawn at hard-coded coordinates. Cell 9 wakes the boss.






  
What had to change

  
Less than nineteen years of bit-rot would suggest. The frameworks it needs — GLUT.framework and OpenGL.framework — are deprecated on macOS but still present and functional in the macOS 26 SDK.

  

  

    
ChangeWhy

    
      
-std=c++03The load-bearing flag. ~200 GLfloat vertex-table entries narrow double→float in braced initialisers — legal in C++03, a hard error from C++11 on.

      
sky1.sgi fallbackThe archive is incomplete. The loader wants 16 textures; this one is missing, and the original called exit(1), so the game died before opening a window.

      
drop Carbon.hIncluded in two files, used in neither. A dead Apple-only API blocking non-Apple builds.

      
asset pathsTextures were fopened by bare filename, so it only ran from one working directory.

    
  

  

  
Plus three genuine bugs fixed: the projection aspect ratio was hard-wired to height/height (so 1.0, squashing the scene in any non-square window), glutInitDisplayMode was called after glutCreateWindow where it has no effect, and glEnable(GL_SHADE_MODEL) is not a valid call at all.






  
The one open bug

  

    
Out-of-bounds write · MainGameRoutines.cp:151

    
The trigger-clearing loop uses <= on both bounds. Map holds 8,382 ints; the maximum index computed is 66 + 66×127 = 8,448 — so it reads, and conditionally writes, 264 bytes past the end of the array, every time an ambush fires.

    
It has never visibly crashed because Map is a global and whatever follows it in BSS absorbs the damage. It is still undefined behaviour, and Emscripten's bounds-checked heap will trap on it. The fix is two characters.

  

  
Fifteen other findings — a stale event-queue reset, a missing break that silently grants rapid fire when you wake the boss, an unchecked RLE decoder — are catalogued in docs/FINDINGS.md. Three blockers, six real bugs, six hazards, three minor.






  
Getting it into a browser

  
It runs. src/gl1/ is a ~900-line shim implementing exactly the thirty-odd OpenGL 1.x entry points this game uses on top of GLES2 — and the game source is unchanged, because gl1.h redirects glBegin, glVertex3f, glTexGeni and friends by macro.

  
It was tractable because of one fact that dominates everything else: this game has no lighting. Not one glLight*, glMaterial* or glNormal3f call outside glutSolidSphere. Fixed-function lighting is normally the hardest part of an OpenGL 1.x migration, and there is none of it here.

The one decision that made it work

  
Vertices are transformed to eye space on the CPU, at glVertex3f time, rather than by a shader. That single choice pays for itself three times over:

  
It leaves the projection matrix as the only per-draw uniform, so geometry batches until the texture changes — the game's roughly 50,000 glBegin/glEnd pairs per frame collapse into about a dozen glDrawArrays calls. It hands GL_EYE_LINEAR and GL_SPHERE_MAP texgen the eye-space position and normal they need, for free, exactly where they are needed. And it costs nothing in fidelity, because the 2007 code has no glPushMatrix anywhere — every draw function manually inverts its own transform — so there is no matrix stack to honour.


  
Why glTexGeni was the real problem

  
The game emits zero glTexCoord2f calls. Every texture coordinate is generated by the fixed pipeline: GL_OBJECT_LINEAR for ground and walls, GL_EYE_LINEAR for turrets, GL_SPHERE_MAP for the boss's chrome. None of it exists in WebGL, and it is the specific thing Emscripten's LEGACY_GL_EMULATION is weakest at — which is why the shim was written by hand instead.

  
The saving grace: the game never sets a custom texgen plane. All planes are OpenGL defaults, so the three modes collapse to simple functions of position and normal, computed CPU-side in the shim. No shader gymnastics, no per-mode variants.

  
One subtlety worth preserving rather than fixing: the game never calls glNormal3f either, so its normal is always GL's default (0,0,1). That is not a bug — it is the behaviour to reproduce, or the boss's chrome comes out looking different.


  
Two traps the browser forced

  
Frame timing. The game is fully frame-locked: every duration is seconds × FRAME_RATE, and the timer was 1000/80 — integer division, so 12 ms, so 83.3 fps rather than the intended 80. requestAnimationFrame gives you 60 Hz or 120 Hz instead, which would run the game 26% slow or 44% fast. A fixed-timestep accumulator now drives it, keeping every frame-counted constant valid.

  
Texture uploads. There is not a single glGenTextures or glBindTexture in the codebase. Every texture change re-uploaded a full 256×256 RGBA image — 15 times per frame, 3.9 MB per frame, ~326 MB/s — to switch between 16 images that never change. Survivable in 2007; browsers will not tolerate it. The shim caches glTexImage2D by pixel pointer, so every call after the first becomes a glBindTexture — the problem disappears with no game-code change at all.

Run it

  
# native — the original fixed-function pipeline
make run

# native — the same game through the new GL shim
make run-shim

# browser — one-time SDK install (~1.5 GB into ./emsdk, gitignored)
make bootstrap
make serve          # http://localhost:8000/tank.html

# W A S D  drive · mouse  aim · space  fire
# P  pause · 1  top view · 0  normal · + −  sensitivity

  
Three builds is deliberate: any rendering bug can be bisected by asking which of the three it appears in. original/ holds the 2007 files byte-for-byte and is never edited; src/ is the working copy, where every divergence carries a [2026 port] comment — so diff -r original src is a complete changelog. TANK_SHOT dumps a frame as a PPM for objective before/after comparison.
